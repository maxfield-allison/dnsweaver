Honour `DOCKER_HOST` (including `tcp://` and TLS via `DOCKER_CERT_PATH` / `DOCKER_TLS_VERIFY`): `DNSWEAVER_DOCKER_HOST` wins, then `DOCKER_HOST`, then the default socket. Previously the default socket was always passed explicitly and overrode `DOCKER_HOST`. In `standalone` mode dnsweaver now pings the daemon at startup instead of calling `/info`, so a locked-down docker-socket-proxy (`INFO=0`) works.
